# Himalayan Local Holdout Prediction Template

Decision: `local_holdout_prediction_template_written_pending_model_outputs`

This template defines the CSV that the local holdout metric report consumes after the leakage audit passes.

| Gate | Value |
|---|---:|
| Production scoring allowed | `false` |
| Himalayan accuracy claim allowed | `false` |
| Template is prediction evidence | `false` |
| CSV filename | `himalayan_local_holdout_predictions.csv` |
| Required columns | 10 |

## Required Columns

| Column | Format | Validation rule |
|---|---|---|
| `holdout_id` | string matching independent_himalayan_holdout.csv holdout_id | must be non-blank and source-governed by a passing leakage audit |
| `valid_at` | ISO-8601 date or timestamp | used for mean and median day accuracy grouping |
| `region_id` | string matching reviewed warning region identifier | used for minimum region accuracy grouping |
| `elevation_band` | reviewed elevation band label or all | kept for future elevation-band accuracy reporting |
| `true_danger_level_1_to_4` | integer from 1 to 4 | must come from reviewed local holdout truth labels |
| `predicted_danger_level_1_to_4` | integer from 1 to 4 | must be generated without using holdout rows for training, calibration, or threshold selection |
| `probability_level_1` | decimal probability in [0, 1] | probability_level_1..4 must sum to approximately 1.0 per row |
| `probability_level_2` | decimal probability in [0, 1] | probability_level_1..4 must sum to approximately 1.0 per row |
| `probability_level_3` | decimal probability in [0, 1] | probability_level_1..4 must sum to approximately 1.0 per row |
| `probability_level_4` | decimal probability in [0, 1] | probability_level_1..4 must sum to approximately 1.0 per row |

## Validation Rules

- Run the local holdout leakage audit before writing or evaluating prediction rows.
- Use one row per holdout prediction unit: holdout id, valid time, region, and elevation band.
- Preserve reviewed five-level source labels elsewhere; this template is the RF4-compatible evaluation view only.
- Do not include any training, calibration, threshold-selection, or non-independent holdout rows.
- Class probabilities must be generated by the frozen candidate being evaluated and must sum to approximately 1.0.
- A filled CSV is not sufficient for a Himalayan accuracy claim until all metric floors and release-gate attestations pass.

## Metric Report Dependency

- Consumer artifact: `himalayan_local_holdout_metric_report.json`
- himalayan_local_holdout_leakage_audit.json decision passes
- himalayan_local_holdout_predictions.csv exists
- all rows satisfy required columns, danger-level ranges, and probability checks

## Claim Boundary

- Production scoring allowed: `false`
- Himalayan accuracy claim allowed: `false`
- Reason: This template defines the required prediction-output shape. It is not evidence, model output, metric proof, or production authorization.
