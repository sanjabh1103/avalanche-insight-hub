Subject: Request for structured scientist validation pilot for Avalanche Insight Hub

Dear Sir / Madam,

We request your support for a bounded scientist-validation pilot of Avalanche Insight Hub, a web-based avalanche prediction and evidence-review platform being prepared for Himalayan use. The platform is ready for scientific verification because it now includes a public forecast workspace, a role-separated scientist workbench, structured review fields using EAWS-style terminology, a two-reviewer governance path for priority cases, an action ledger, daily scientist-vs-model comparison, and exportable sign-off packets.

This request is for validation and co-working only. We are not claiming operational warning authority, production SAR promotion, public model promotion, or completed Himalayan scientific proof from the current implementation. Scientist reviews can accept limitations, reject claims, request more evidence, downgrade claims, or block claims. They will not automatically retrain the model or change public forecast claims without separate governance approval.

## What We Request From SASE / DGRE

| Request | Details |
|---|---|
| Pilot region | Please nominate one Himalayan pilot region suitable for an 8-week validation pilot. |
| Historical cases | Please share 20-30 historical or recent avalanche cases suitable for scientific validation. |
| Bulletin archive | Please share available avalanche bulletins or danger assessments for the selected region and winter season. |
| Weather / station data | Please share station observations, gridded weather, snowfall, wind, temperature, and precipitation records where available. |
| Field reports | Please share field observations, avalanche occurrence reports, terrain notes, or post-event reports where available. |
| Snowpack / HIM-STRAT data | Please share snow-profile, weak-layer, stability-test, or HIM-STRAT-compatible parameters if available. |
| Reviewers | Please nominate one or more scientists who can review cases, complete structured verdicts, and advise on terminology. |
| Data terms | Please confirm confidentiality, attribution, publication, and training-eligibility boundaries for shared data. |

## Proposed Meeting Workflow

| Step | Purpose | Expected output |
|---:|---|---|
| 1 | Briefly introduce the public forecast workspace and scientist workbench. | Shared understanding of what the platform currently does and does not claim. |
| 2 | Demonstrate one clearly marked synthetic case. | Confirm workflow usability without treating demo data as scientific evidence. |
| 3 | Review 3-5 public-source candidate Himalayan cases. | Mark each as confirm, reject, uncertain, or needs more evidence. |
| 4 | Complete the pre-meeting questionnaire. | Capture scientific thresholds, false-alarm tolerance, evidence priorities, and no-go promotion conditions. |
| 5 | Export a sign-off packet. | Produce a dated record containing cases, reviews, actions, references, reviewer count, disagreement count, and claim boundaries. |

## Governance Boundary

All synthetic demo data remains excluded from training, public scoring, and production promotion. Public-source Himalayan candidate cases remain unconfirmed until SASE / DGRE or another qualified scientist confirms them. European shadow evidence and Modal.com GPU runs are used only as benchmark, research, or candidate-model evidence; they do not prove Himalayan accuracy.
